## 1. 先修正判断方式

“小机制”“使用已有组件”“可以写成一个 rewrite”都不能直接判定没有科研价值。
应分别判断：问题是否重要；是否发现非显然的原因；机制相对最强合理方案
增加了什么；完整路径上的收益、正确性、适用范围与失败边界是否成立。
系统论文可以是新技术，不必硬造一个新问题，也不必强行同时使用端云和 NPU。

当前必须分开三种状态：

| 状态 | 当前实例 | 后续处理 |
|---|---|---|
| 已有机制的有效工程优化 | C06 消费就绪缓存，完整 action flow 约 7.4% 收益 | 作为后续强起点，并完成真实观测集成；不能拿更差的提交路径反复计收益。 |
| 实测落败的具体机制 | C14 的 compact repeat/grouped 子图 | 停止推进该版本；更快的内核不能抵消已测出的完整路径损失。 |
| 已测局部增量、全策略未验证 | 紧凑并行与原生位复制恢复共存 | 单块中位数/已测数值过关，尾延迟/重要性/泛化仍需核验；不因小就否定，也不直接升主线。 |

“强基线”不意味着优化不重要。反过来，若发现一套现有工具不能直接解决的
规律，并提出有效机制，小实现也可以成为主贡献。不能把自己的新机制先称为
基线，再要求它超过自己；应比较已知、合理、可独立实现的最强方案。

## 2. 当前发现指向哪里

| 已测事实 | 可保留的推论 | 不能推出的结论 |
|---|---|---|
| 紧凑 grouped 的 Attention 核心 profile 为 541 us，原融合为 862 us；动态 Q 重排却为 1206 us | 瓶颈可能转移到动态数据的组织方式，值得检查真实生产/消费边界 | 新 grouped 方案已更快；重排可以免费消除；所有层都有同样收益。 |
| 普通消费就绪缓存完整 flow 为 692.65/693.32 ms，准备约 10.44/10.46 ms 已计入 | 后续必须超过这个强 action-runtime 起点；静态 K/V 工作已经大幅外提 | 这是完整 VLA 时延；额外隐藏准备还能带来巨大收益。 |
| 单视角 head 并行改善约 31%，双视角强对照后只余约 4%-6% | 不同独立维度会争用同一资源，必须以实际工作负载选择对照 | 更细 overlap 必然更好；NPU busy 更高就是有效利用率更高。 |
| 固定 conditioning 的 expanded native state 为 9.339 MB，compact 对应形状约 3.113 MB | 存储、传输、消费布局应分别计费 | 已有内存容量问题；物理 DDR 流量必然放大三倍。 |

最有价值的变化是：**不是继续消除静态条件的重复准备，而是检查动态数据
是否被迫先生成一种不适合后续计算的表示，再反复修正它。** 这是从失败数据
产生的新假设，不是把 C14 的失败改写成胜利。
尤其要防止探针制造痛点：1206 us 来自本次 grouped 子图及其选定的 native
输入 ABI，不是已经证明原完整网络也支付了同样的开销。它可能只是一个坏接口。
因此下一步先检查真实上游能否提供另一种表示，不把探针异常直接写成部署痛点。

## 3. 下一轮顺序

| 顺序 | 要回答的问题 | 定位与交付物 |
|---|---|---|
| P0 | 强优化接真实观测后，完整 VLA 的剩余关键路径在哪里？ | 三帧完整重放已补，视觉约 53%。闭环/更多任务未测，不是新论文机制。 |
| P1 / C17 | 原生位恢复的局部增量，在真实策略中是否重要且稳定？ | 观测驱动重放通过，局部约 1.2 ms/block；重要性不足以支持直接全层扩展。找另一重要同因边界，尾部根因仍开放。 |
| P2 / C08 | 热点内部是否有阶段赢家反转，值得 CPU/NPU 在内部交接？ | 有停止条件的诊断；先测部件与交接，不直接实现 tile 系统。 |
| P3 / C04 | 分支分工会不会改变端侧最佳并行维度，且胜过强全端/流式全云？ | 实际 PNG 57-66 KiB，紧凑无损特征约 111 KiB；不靠省字节。先测 branch 服务矩阵/数值与链路可行域，不先建迁移调度器。 |

三条候选分别改变**本地表示边界、算子内部设备边界、远端任务边界**。
它们不是一篇论文的三个必选模块，也不是一个失败后另一个自动接任。
P1 先做是因为证据最近、实验最小，不代表它的论文价值已经最高。

### P0：先把局部结果放回真实 VLA

使用同一 checkpoint、真实 LIBERO 双视角输入、相同指令/状态与相同 noise，
比较原 native 策略和只加入 C06 的策略。保持十步与 FP32 latent/Euler。
先固定输入采集配对时延与逐步输出，再独立验证闭环；不把固定输入测试当成功率。
分开记录图像准备、双视角编码、prefill、条件准备、十步 action、输出交接。

不能把旧 3.236 s、此前 793 ms、本轮 693 ms 从不同测量环境拼成优化后总时延。
新测量统一 CPU affinity、图版本、输入边界，记录 NPU/DRAM/CPU 频率与温度；
独立进程测模型/缓存常驻内存，不从四 context 共存实验推断部署 peak RSS。

再做一轮有针对性的 Roofline 诊断：区分实际有用计算、编译展开、布局变换、
提交与同步。频率敏感性可帮助定位，但不能单凭频率扫描或 busy 判定瓶颈；
实际硬件计数器不可得时，明确报告带宽/占用率结论的限制，不把 SDK RW 当 DDR。
没有这个强优化后的关键路径，暂不承诺端到端提升比例。

### P1 / C17：不要先生成一个需要昂贵重排的 Q

**直白痛点：** 已测 grouped 子图让计算内核更快，却先要求把每一步新产生的
Q 换一种排列；换排列比计算节省还贵。K/V 能一次整理，Q 每一步都变，不能
套用同样的静态缓存办法。

**动机：** 上次子图从已经生成的 Q 开始，测的是“生成既定 Q 后再适配”。
它没有回答：如果连真实 Q 投影及其相邻操作一起编译，是否可以以适合消费的
表示生成动态 Q，并让后续输出投影接受同样的排列，而不在两个边界恢复默认布局？

**候选机制：** 选择一次完整 Q producer -> Attention -> output projection
的执行表示。静态 K/V 只准备一次；动态 Q 不先固定为孤立探针的输入 ABI。
按语义允许的维度传播 layout，尝试 group/head 子图的 native view，只有必要时
才显式重排。比较计算几何的收益与生产、消费、同步、临时状态的完整代价。

这里有一个硬约束：token/head 的转置一般不能只靠重排线性层权重免费吸收。
仅 channel permutation 可以在相应线性层中代数重索引；涉及 token 轴时，必须
证明真实编译输出/native view 支持它，或者完整计入转换。reshape 也不默认零成本。
本候选不改权重的数学作用，不训练，不删 Q heads，不从输入删除 padding 后漏算 mask。

**最小实验：** 先只取真实 layer 1，包含 Q 投影前后的实际归一化/位置变换、
Attention、真实输出投影；先确认具体依赖，再确定边界，不能为了方便遗漏算子。
四种同输入、同输出接口的配对控制：

1. C06 的 expanded consumer-ready 条件 + 原融合 block。
2. compact grouped + 显式重排的原失败路径，确认完整边界后仍能复现原因。
3. producer/consumer 一起编译的 grouped 路径，检查编译器是否实际消除或移动转换。
4. 普通 native head 分区/更合适的图接口，检验无需特殊机制的简单替代方案。

准备成本按每观测一次计入；动态转换、FD alias 检查、cache sync、图启动和
输出交接全计入。SDK profile 只解释原因，正式计时是完整 block。
先核验 FP32 代数等价，再对原 FP16 后端作逐步数值检查；数学等价不等于
后端逐位一致。出现新增系统性误差时，不称无损，也不直接推进完整策略。

**潜力与边界：** 用单层 ready 878 us 与 grouped 541 us 的 profile 差，粗乘
16 cross 层和十步得到约 54 ms，只是待验证量级估计，不是完整图上界或预测。
它还假设转换完全消失、所有层同收益且 profile 可迁移，均未成立。
即使成立，也只是 action flow 的一部分；单凭这个量级不宣称足够支撑 CCF-A。
随后要检验不同真实 layer、query/prefix 长度，以及兼容的 VLM GQA 工作负载。
不改变正式策略的动作数；shape 变化用于机制适用范围，不拿少算动作取得收益。

**升格条件：** 完整边界胜过最强控制，并能解释何时值得改变表示、何时保持融合。
若只有固定 shape 的普通 fusion/transpose 修复，保留工程结果；若新机制在多个
几何下解决可重复的非显然限制，则保留为研究路线，不因实现小就自动降级。
若真实 producer 不能提供兼容布局，或转换只是藏进其内部并仍支配路径，停止该版本。

### P2 / C08：是否存在值得在算子内部交接的异构分工

**直白痛点：** 把整段 Attention 放到 CPU 没测出优势；但整段比较无法说明
矩阵计算、归一化、布局整理是否由同一种设备高效完成。我们尚未发现阶段反转。

**候选机制：** 若实际数据证明 NPU 在 QK/PV 上占优，而 CPU 在归一化或必要
布局操作上占优，可以尝试按 head/query tile 流水交接，而非整段迁移。
保留全 K/V 依赖；稳定 softmax 的归一化不能错误地局限在部分 K tokens。
优先固定同观测 K/V，把交接限制在动态 tile；不将共享 DRAM 称为片上驻留。

**先做的诊断：** 在真实 vision 长 query 与 action 短 query 上分别测 QK、
稳定归一化、PV、buffer 交接。必须同时保留完整 fused Attention 控制；分项
之和不是 fused 路径，CPU FP32 优于 Torch FP16 也不是同精度硬件反转。
检查矩阵接口、native layout、同步粒度能否支持实际管线，不能假定可编写任意 NPU kernel。

**只有诊断成立才实现：** 一个实际 block 的双缓冲流水，以及同样分块但全部
放 NPU 的控制。全矩阵、全部 head/token 与数值协议保留，不换低精度换速度。
完整阶段与同步测量不能证明剩余空间时停止；旧 37.38 -> 37.31 ms 的跨算子
负结果不能当作内部合作已失败，但也不能被忽略后再宣称 overlap 必然有效。

它的潜在价值是发现“一个热点内部也会换设备赢家”，而非写一个通用 scheduler。
目前只是条件式候选，不能写成已发现 vector/softmax 是 NPU 的真实瓶颈。

### P3 / C04：端云合作先找传输与完成时间的交叉点

**直白痛点：** 云算得快，但必须先拿到完整输入；端侧已经能做一些视觉工作，
却可能因太慢成为最后等的支路。两种代价到底在哪里交叉，目前没有数据。

**候选问题：** 对同一观测的独立相机编码，是否存在按分支、传输对象与已完成
进度组织协作的合理胜区，而不是对整模型搜索层切点？本 checkpoint 的双视角
是评测配置，不假定所有 VLA 都双视角；只有独立视觉 encoder 可按相机分开，
不能把会混合相机 token 的多模态 prefill 也错误地拆成互不相见的支路。

**最小审计：** 用同一真实输入测原始 uint8 图像及无损编码、connector features、
prefix K/V 的实际字节、编码/解码、服务时间与 native 准备成本。传输字节级
保真，比较相同模型目标精度；不能默认 float16 转换或 JPEG 是无损传输。
若跨后端数值不同，分别对各自单机 anchor 核验，不冒充端云逐位一致。

比较优化全端、完整全云、最好静态相机分工和普通 hedge。全云也能逐相机
上传并重叠云计算，不以“等所有数据到齐才开始”的低效全云作对照。
共享上传链路的两支不能都按独占带宽计时；明确图像/feature 的发送时机、
preparation、云排队与最终 join，单请求总时延从同一观测到达开始计。

在真实链路与明确受限网络条件下画可行域，离线 oracle 也算出最好可能值。
若 oracle 都不能胜过全云/全端，就不建调度器。若静态分工已吸收全部收益，
留下工程结论；只有出现实际剩余工作/传输进度导致的反复 winner crossing，
才研究按剩余关键路径切换，并计入重启、重复传输与取消成本。
固定云预算下的多机器人容量是另一个目标，需另设排队实验，不能偷换单请求目标。

## 4. 本轮文献自审

本轮重新核验以下原始来源；它们界定边界，不证明我们的候选已经新颖：

- [FlashAttention 官方实现](https://github.com/Dao-AILab/flash-attention)：已经
  支持少于 Q heads 的 K/V heads。GQA sharing/group packing 本身不是 C17 的新点。
- [Welder，Shi 等，OSDI 2023](https://www.usenix.org/conference/osdi23/presentation/shi)：
  已将跨算子 tile 数据复用和内存访问纳入统一优化。C17 不能只声称“联合上下游
  优化 layout”；需要证明移动 NPU 的实际边界限制及机制增量。
- [HeteroInfer，Chen 等，SOSP 2025](https://arxiv.org/html/2501.14794v2)：
  已研究移动 NPU 的 shape/order sensitivity、tensor partition 和异构同步。
  C08 不能只说“按特征选择后端”，C17 也不能只说“张量排列很重要”。
- [RoboECC，Zheng 等，2026](https://arxiv.org/html/2603.20711v1)：已经考虑
  VLA 的模型/硬件切分与网络变化。C04 不能以“动态带宽决定端云位置”单独立题。

C17 的具体 producer/consumer ABI 机制、C08 的内部流水机制、C04 的分支剩余
进度机制都尚未完成新颖性证明。只有最小实验支持核心机制，才继续扩大近邻检索。
未检索到直接重叠不等于此前无人做过。

## 5. 明确不继续包装的方向

- C14 原 compact/grouped 消费路径：完整子图落败，不调阈值救它；C17 是新的
  生产/消费边界实验，其成立必须重新给证据。
- 仅把 preparation 与首步重叠：本次准备约 10.4 ms，就算完全隐藏也是小量级。
  C15 的 prefix/首步重叠最多隐藏一个首步的关键路径，不能按十步乘收益。
- 9.339 MB 常驻条件本身：未发现容量瓶颈，不制造多请求/内存不足来救故事。
- 图锁全部 NPU 核：已有 companion 反例，不能作为动机。
- 有损视觉复用、减动作/步骤、相似动作验收：不在本轮 scope。
- SmolVLA flow 投机：仍缺兼容原确定性 FP32 Euler 协议的严格验证器，不把
  AR 投机的接受规则直接搬过来；Agent/大小脑/长程规划目前不充当装饰模块。

2026-09-29 更新后的执行顺序是：真实策略强基线与分项；C17 新位恢复变体
的重要性/适用域及尾延迟诊断；再独立考虑 C08 阶段诊断及 C04 payload 审计。
数值来源定位和原生 head 强对照已完成，不能用初轮旧方案代替最新胜者。
当前没有已闭合的 CCF-A 主线；也不提前把所有未测机制
归为基线。后续选择以实测的重要障碍、机制增量和完整收益为准。
